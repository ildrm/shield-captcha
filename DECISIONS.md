# Implementation decisions

| Decision | Basis |
| --- | --- |
| Laravel 13.44.1, Filament 5.12.0, Livewire 4.4.10 | Composer resolved patched upstream packages against PHP 8.3 using refreshed official Packagist metadata. The archives installed on PHP 8.5.8 and the fresh advisory feed found zero applicable advisories. [Laravel deployment](https://laravel.com/docs/13.x/deployment), [Filament installation](https://filamentphp.com/docs/5.x/introduction/installation), [Packagist advisory API](https://packagist.org/apidoc#list-security-advisories) |
| Single PHP application and two Filament panels | Tenants share an InnoDB schema. The customer panel uses organization-scoped resources and policies. The operator panel uses a dedicated guard, dedicated identity and TOTP. Customer routes use `/customer` and operator routes use `/admin`. [Filament tenancy](https://filamentphp.com/docs/5.x/users/tenancy), [Filament MFA](https://filamentphp.com/docs/5.x/users/multi-factor-authentication) |
| Standalone pilot provider | Use bounded SHA-256 work in one browser worker and state on the server. ALTCHA v2 uses a different protocol and this release does not claim compatibility. The provider needs independent review and low-end-device measurement before a commercial pilot. [ALTCHA documentation](https://altcha.org/docs/) |
| Static public assets and cron | Laravel serves Blade content, the widget is static, and Filament ships compiled assets. The host package includes dependencies and serves without Node. Cap scheduled deletes and avoid permanent processes. |
| SMS Scope | Fixed windows and a destination cooldown supply deterministic recommendations. The customer owns SMS sending and send-level idempotency. Use a tenant-controlled HMAC of the normalized destination. |
| ZarinPal billing | Hosted Iranian-rial checkout, one manually renewed fixed term, immutable invoice amounts and paid quota snapshots. Sandbox settlements remain isolated. [ZarinPal gateway documentation](https://www.zarinpal.com/docs/paymentGateway/connectToGateway) |
| Kavenegar delivery | Approved OTP templates and tenant-owned provider accounts. A dedicated site credential controls spend. Ambiguous transport outcomes require reconciliation and keep the original event reserved. [Kavenegar REST documentation](https://kavenegar.com/rest.html) |
| Stripe checkout | Reuses the fixed paid term and invoice settlement. The session is verified against the stored amount, currency, environment and purchase context. Signed webhooks cover payments when the customer does not return. [Stripe fulfillment](https://docs.stripe.com/checkout/fulfillment.md?ui=full-page) |
| Twilio delivery | Uses the Messages resource to send the OTP generated by the customer's backend. The carrier receives an E.164 number and a transactional message, and each site uses its own credentials. [Twilio Messages API](https://www.twilio.com/docs/messaging/api/message-resource) |
| Active providers | Operators can enable both payment gateways together and choose a single SMS provider. Database settings supersede the legacy environment defaults after the first save. Payment recovery stays tied to the invoice, and OTP replay stays tied to the delivery record. |
| JSON-form OpenAPI | The canonical `openapi/v1.yaml` uses JSON syntax, a YAML 1.2 subset, to support both parsers. Package archives in `downloads/` are build outputs with real checksums. |
